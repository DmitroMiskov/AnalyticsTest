# Контекст проєкту та регламент роботи: мережа кав'ярень «Зерно»

Цей файл описує контекст, бізнес-логіку та непорушні правила обробки даних для роботи ШІ-агентів у проєкті мережі кав'ярень «Зерно».

---

## 1. Контекст бізнесу
* **Мережа**: 10 кав'ярень у Києві (4 точки), Львові (3 точки) та Одесі (3 точки).
* **Графік роботи**: 2 зміни щодня у кожній кав'ярні — ранкова (07:00–15:00, 8 год) та вечірня (15:00–22:00, 7 год).
* **Персонал**: 1 бариста на зміні (усього 33 штатні бариста за довідником HR).
* **Касові системи**: дані експортуються з трьох незалежних регіональних серверів (Київ, Львів, Одеса) і склеюються щотижня.
* **Оцінки клієнтів**: планшет біля каси (шкала 1–5). Оцінюють не всі клієнти (~2–5% чеків). Якщо оцінок 0, `Середня оцінка` = `NaN`.

---

## 2. Непорушні правила перевірки та обробки даних

1. **Жодних чисел «з голови»**:
   * Усі показники, висновки та таблиці повинні бути розраховані виключно кодом і відтворюватися скриптом `build.py`.
2. **Заборона прихованих змін**:
   * Будь-яка зміна даних логується: що було, що стало, скільки рядків зачеплено, бізнес-обґрунтування.
3. **Зважені середні (`sum / sum`) замість «середнього середніх»**:
   * Середній чек мережі чи точки рахується як `sum(Виручка) / sum(Чеків)`. Заборонено усереднювати показники окремих днів чи кав'ярень без ваги чеків.
   * Середня оцінка бариста рахується як зважена: `sum(Оцінка × К-ть_оцінок) / sum(К-ть_оцінок)`.
4. **Обов'язкова перевірка зсувів (Biases)**:
   * **Календарний зсув**: кав'ярня «Київ · Теремки» відкрита 15.05.2026 (працювала 129 днів проти 173 в інших). Заборонено порівнювати абсолютну виручку без нормування на дні роботи.
   * **Зсув локації**: середній чек на Хрещатику (~128 грн) на 50% вищий, ніж на Таїрова (~85 грн). Порівняння співробітників за абсолютним чеком неприпустиме.
   * **Зсув часу зміни**: ранкова зміна завжди має вищий середній чек (~109 грн), ніж вечірня (~91 грн).
   * **Ефект малої вибірки**: обов'язковий ценз стажу для бариста (мінімум 60 змін) перед оцінкою рейтингу.
5. **Захист від псевдоефектів маркетингу**:
   * Перевіряти «регресію до середнього»: якщо для акції обрали точки з найбільшим травневим просіданням, їхнє зростання влітку зумовлене відновленням та сезоном.
   * Обов'язкове використання контрольної групи (Difference-in-Differences). Не робити висновків про причинність без контролю.

## 3. Регламент assert-перевірок
Кожне очищення повинно завершуватися перевіркою:
* `df.duplicated(subset=['Дата', "Кав'ярня", 'Зміна']).sum() == 0` — унікальність зміни.
* `df['Дата'].min() >= '2026-04-01'` та `df['Дата'].max() <= '2026-09-20'`.
* `set(df["Кав'ярня"]).issubset(set(df_cafes["Кав'ярня"]))` — відомі локації.
* `set(df['Бариста']).issubset(set(df_baristas['ID бариста']))` — відомий персонал.
* Перевірка строгих числових типів (`int` для чеків/годин/оцінок, `float` для грошей/середніх).
